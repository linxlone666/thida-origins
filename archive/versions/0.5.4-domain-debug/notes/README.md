# ธิดา — Origins สำหรับ Minecraft Forge 1.20.1

รุ่น **0.5.4-domain-debug** สำหรับทดลอง ใช้ HUD Lite พร้อมคำสั่งผู้ดูแลรีเซ็ตคูลดาวน์/ตรวจสถานะ/ยุติพลัง และคำสั่งจัดตำแหน่ง HUD ฝั่ง client

## ติดตั้ง

1. Minecraft Java **1.20.1**, Java **17**, Forge **47.4.0**
2. Origins Forge **1.20.1-1.10.0.9** และ Caelus **3.2.0+1.20.1** ตาม dependencies เดิมของโปรเจกต์
3. ใส่ `thida-origins-1.20.1-0.5.4-domain-debug.jar` ใน `mods` ทั้งเครื่องผู้เล่นและเซิร์ฟเวอร์ แทน JAR ธิดารุ่นเดิม
4. เลือก Origin **ธิดา** จะได้รับนิลกาลและนรตราอัตโนมัติ ใช้ `/thida kit` รับไอเทมสกิลทั้งหมด

Origin และทรัพยากรรวมอยู่ใน JAR ไม่ต้องติดตั้ง ZIP ซ้ำ สำหรับโลกเดิมใช้ Orb of Origin หรือ `/origin set <ชื่อผู้เล่น> origins:origin thida:thida`

## การควบคุม

ตั้งปุ่มเปิดเมนูได้ที่ **Options → Controls → Key Binds → ธิดา → เปิดเมนูหุ่นฟาง** (อังกฤษ: Thida → Open straw-doll menu) ค่าเริ่มต้นคือ **R** ตั้งเป็นคีย์อื่นหรือปุ่มเมาส์ได้ ในเมนูใช้ **1–3 ส่งผล / 4 ยกเลิก** หรือคลิกปุ่มภาพ


- **นิลกาล:** ถือหุ่นตีผู้เล่นเพื่อเชื่อมเป้าหมายดีบัพ
- **นรตรา:** ถือหุ่นมองหน้าผู้เล่นต่อเนื่อง 10 วินาทีเพื่อเชื่อมเป้าหมายบัพ อีกฝ่ายไม่ต้องมองกลับ
- **สกิล 1:** ถือหุ่น Passive แล้วกด **R** เปิดเมนู จากนั้น **1 / 2 / 3** ส่งผล หรือ **4** ยกเลิกการเชื่อม; Esc ปิดเมนู
- ปุ่มเปิดเมนูใช้ขณะเล่น ไม่มีหน้าจออื่นเปิดอยู่ เลือกหุ่นมือหลักก่อนมือรอง และไม่เปลี่ยนช่อง hotbar เมื่อปุ่มเปิดเมนูถูกตั้งเป็นเลข
- ทางเลือก: Shift+คลิกขวาหุ่นเพื่อวนเลือกผล และคลิกขวาเพื่อส่งผล
- **สกิล 2:** คลิกขวาไอเทมหุ่นกาฝากเพื่อเสกหุ่น แล้วตีผู้เล่นเพื่อเชื่อม คลิกขวาอีกครั้งเพื่อยกเลิก
- **สกิล 3:** ถือหุ่นพันธะ เล็งผู้เล่นแล้วคลิกขวา คลิกขวาอีกครั้งเพื่อยกเลิก
- **โดเมน:** คลิกขวาเครื่องราง ศูนย์กลางคือพิกัดผู้ใช้ตอนกางและไม่เคลื่อนตามตัว

## คำสั่ง Debug สำหรับทดลอง

คำสั่งต่อไปนี้ต้องเป็น OP / มีสิทธิ์คำสั่งระดับ 2 หรือเปิด cheats ในโลกเดี่ยว หากไม่ใส่ชื่อผู้เล่นจะใช้กับตัวเอง Console ต้องระบุชื่อ:

| คำสั่ง | ผล |
|---|---|
| `/thida resetcooldown [ชื่อผู้เล่น]` | ล้างคูลดาวน์ทั้งหมด ทั้งหุ่น ผลสกิล และโดเมน เก็บเป้าหมาย ผลที่กำลังทำงาน และสิทธิ์อมตะที่ใช้แล้วไว้ |
| `/thida debug status [ชื่อผู้เล่น]` | แสดง HP, เป้าหมายที่เชื่อม, สถานะล็อก, สิทธิ์อมตะ, เวลาผลและคูลดาวน์ |
| `/thida debug end [ชื่อผู้เล่น]` | ยุติการเชื่อมของหุ่น/พันธะและโดเมน ลบหุ่นกาฝากที่เสก โดยไม่ให้ฮีลรางวัลหรือทำให้ธิดาเลือดไหล เริ่มคูลดาวน์ปกติ |

`resetcooldown` ไม่ยุติโดเมนที่กำลังทำงาน จึงกางซ้อนไม่ได้จนโดเมนเดิมสิ้นสุด ถ้าต้องการเริ่มทดสอบใหม่ทันที ใช้ **debug end → resetcooldown** ตามลำดับ บัพ/ดีบัพที่ส่งให้คนอื่นไปแล้วจะหมดตามเวลาปกติ ไม่ถูกล้างด้วย debug end

## ย้าย HUD ในเกม (ไม่ต้องเป็น OP)

```text
/thidahud position 20 80
/thidahud rows 4
/thidahud preview
/thidahud reset
```

- `position`: x วัดจากซ้าย, y วัดจากบน หน่วยพิกเซล GUI ตาม GUI Scale; ค่าใหญ่เกินจอจะถูกจำกัดไม่ให้ HUD หลุดจอ
- `rows`: จำนวนไอคอนต่อแถว 1–12
- `preview`: แสดงไอคอนตัวอย่างมีอักษร P นาน 10 วินาที ให้ปิดแชตเพื่อดู ไม่สร้างผลสกิลหรือคูลดาวน์จริง
- `reset`: คืน x=8, y=8 และ 6 ไอคอนต่อแถว
- `/thidahud` อย่างเดียวแสดงค่าตำแหน่งปัจจุบัน

ตำแหน่งและจำนวนไอคอนบันทึกลง `config/thida-client.toml` ของเครื่องผู้เล่นทันที หรือปิดเกมแล้วแก้ `hudX`, `hudY`, `iconsPerRow` ในไฟล์โดยตรงก็ได้ HUD ต้องเปิด `showHud=true` จึงเห็น preview

Debug เป็นรุ่นแยกอยู่ใน `release/0.5.4-domain-debug` รุ่น Lite เดิมยังอยู่ใน `release/0.5.0-lite` ติดตั้ง JAR ธิดาเพียงรุ่นเดียวทั้ง client/server
## HUD Lite — เฉพาะตอนใช้สกิล

ไม่มีแผงข้อความหรือรายชื่อเป้าหมายค้างบนจอ ไม่มีไอคอน “พร้อม” แสดงตลอดเวลา เมื่อใช้สกิลจึงขึ้นไอคอนเล็ก:

1. **ผลสกิลทำงาน:** ไอคอนสว่าง ขอบเขียว นับเวลาที่ผลยังอยู่
2. **ผลหมด:** เปลี่ยนเป็นไอคอนมืด มีคำว่า CD และนับคูลดาวน์ที่เหลือจริง
3. **พร้อมใช้:** ไอคอนหายไป และมีเสียงแจ้งพร้อมใช้ตามการตั้งค่า

บัพ 20 วินาที / คูลดาวน์ 30 วินาทีที่เริ่มตั้งแต่กด → แสดงผล 20 วินาที แล้ว CD อีก 10 วินาที ไม่เพิ่มคูลดาวน์เป็น 50 วินาที ล้างสถานะเป็นผลทันที จึงแสดง CD เลย ส่วนบัพความเร็ว+ฮีลนับเฉพาะความเร็ว ฮีลทำทันที

เวลา active ส่งจากเซิร์ฟเวอร์และจำกัดตามเอฟเฟกต์ที่ยังอยู่บนเป้าหมาย ถ้าถูกล้างก่อนครบเวลา ไอคอนจะเข้า CD โดยไม่รีเซ็ตคูลดาวน์ การใช้ไม่สำเร็จไม่สร้างไอคอนใหม่

- กาฝากและพันธะหทัยแสดง ∞ ขณะทำงาน เพราะไม่มีระยะเวลาตายตัว เมื่อยกเลิกจึงนับ CD 10 นาที
- โดเมนแสดง active 5 นาที → CD 20 นาที → หาย
- คูลดาวน์ยกเลิกหุ่น Passive แสดงไอคอนตัวหุ่นแยกจากไอคอนผลสกิล
- การมองนรตราแสดงไอคอนชั่วคราวพร้อม G และเวลาที่ต้องมองต่อ ไม่แสดงมาร์คถาวรบน HUD
- ชื่อเป้าหมายยังดูได้ในเมนูหุ่น ปุ่มเปิดเมนูเปลี่ยนได้ใน Controls (เริ่มต้น R); ใช้ 1–3 ส่งผล และ 4 ยกเลิก
- ผู้รับพันธะเห็นไอคอนหัวใจ และไอคอนอมตะนับ 5 วินาทีเมื่อเกิดการช่วยชีวิต

ใช้ไอคอนพิกเซลเดิม ขนาดช่อง 34×35 พิกเซลในหน่วย GUI แถวละ 6 ช่องโดยค่าเริ่มต้น ไม่มีแผงแจ้งข้อความยาวจาก HUD แต่เสียงสถานะยังอยู่

ตั้งค่าใน `config/thida-client.toml`: `showHud`, `cueSounds`, `cueVolume`, `hudX`, `hudY` และ `iconsPerRow` (1–12) HUD ซ่อนขณะเปิดหน้าต่าง / F1 / F3 เช่นเดิม

**เป็นตัวเลือกแยกจากรุ่นเต็ม 0.4.1** ซึ่งยังอยู่ใน `release/0.4.1` รุ่น Lite อยู่ใน `release/0.5.0-lite` ใช้ JAR ธิดาเพียงรุ่นเดียว และติดตั้งรุ่นเดียวกันทั้ง client/server เพราะเพิ่มข้อมูลเวลาผลสกิลใน packet

พลังเก่า Ward, Veil, Grace, Remedy และ Herbal Orb ยังคงยกเลิกแล้วเหมือนรุ่นเต็ม
## Config และโลกเดิม

Config อยู่ที่ `<โลก>/serverconfig/thida-server.toml` รุ่นนี้ใช้คีย์ใหม่ `domainActiveSeconds=300`, `dollEffectSeconds=20`, `parasiteCasterBreakHealth=25` เพื่อไม่รับค่าฉบับเก่า 15/10/50 โดยไม่ตั้งใจ คีย์เก่า `domainDuration`, `effectSeconds`, `parasiteBreakHealth`, `parasiteThreshold`, `markRange` ไม่ใช้แล้ว

คูลดาวน์ส่งผลแยกประเภท 30 วินาที; คูลดาวน์หลังยกเลิกหุ่น/พันธะ 600 วินาที; โดเมนคูลดาวน์ 1200 วินาทีหลังหมดเวลา 300 วินาที

ค่าที่คงเป็นสมมติฐานปรับได้: แบ่งดาเมจ 50/50, ฮีลนรตรา 8 HP, ดีบัพรับดาเมจเพิ่ม 30% ส่วนฮีลหลังหุ่นกาฝากแตกเพิ่ม 50 HP ตามสเปก โดยจำกัดที่ max health ปัจจุบัน **2 HP = 1 หัวใจ** ม็อดไม่เพิ่ม max health ให้เอง

หุ่นกาฝากที่เสกใช้ Armor Stand ขนาดเล็กหัวฟักทองเป็นรูปลักษณ์ชั่วคราว นรตราในโดเมนยังหมายถึงผู้เล่นที่เชื่อมกับหุ่น เช่นเดียวกับระบบเดิม ไม่มี AI หุ่นต่อสู้แยกตัว

## เอฟเฟกต์โดเมน 0.5.4-domain-debug

ใช้ยันต์โดเมนด้วยคลิกขวาตามเดิม เอฟเฟกต์เป็นธีมคำสาปหุ่นฟางที่ได้แรงบันดาลใจจากการกางอาณาเขต:
- เปิดพลังด้วยเสียงชาร์จต่ำและเปลววิญญาณ วงสีแดงม่วงแผ่ออกถึงรัศมีที่ตั้งไว้
- ภายใน 3 วินาที เส้นคำสาปถักขึ้นเป็นโดม ตามด้วยเสียงกระแทกพลัง
- ระหว่างโดเมนทำงาน มีวงอาคมสีทองตรงศูนย์กลางเดิม และเส้นขอบทรงกลมแบบโปร่งตามระยะสกิล
- หมดเวลาหรือใช้ /thida debug end จะมีควันสลายและเสียงปิดโดเมน

เป็นภาพเรืองแสง เสริมด้วยอนุภาคและเสียงในโลกที่ผู้เล่นใกล้เคียงรับรู้ได้ ไม่สร้างบล็อก ไม่เปลี่ยนดาเมจ/คูลดาวน์ และไม่มีการสั่นกล้องหรือเอฟเฟกต์บังจอ กราฟิกอนุภาคของ Minecraft มีผลต่อจำนวนที่มองเห็น เสียงอยู่ในหมวด Players

ทดลองซ้ำ: /thida debug end ตามด้วย /thida resetcooldown แล้วคลิกขวายันต์โดเมนอีกครั้ง คำสั่ง HUD และ Debug จากรุ่นก่อนยังใช้ได้ ติดตั้ง JAR ธิดาเพียงไฟล์เดียว โดยใช้รุ่นนี้ทั้ง Client และ Server

## โดเมนและหุ่นโฉมใหม่ — 0.5.3

โดเมนเพิ่มเส้นเรืองแสงต่อเนื่อง วงขอบสามชั้น เส้นโค้งทรงกลม 12 แนว วงแหวนบนโดม 3 ชั้น เสาพลัง 8 จุด และวงอาคมดาวหกแฉกหมุนตรงกลาง ภาพส่วนนี้ไม่ขึ้นกับการตั้งค่าจำนวนอนุภาค ใช้เวลาเปิด 3 วินาทีเท่าเดิม ผู้เล่นในมิติเดียวกันที่อยู่ภายในรัศมีโดเมน + 96 บล็อกจะได้รับข้อมูลภาพ (ค่าเริ่มต้น 126 บล็อกจากศูนย์กลาง) สิ่งก่อสร้างและภูมิประเทศยังบังภาพตามปกติ

หุ่นกาฝากไม่มีป้ายชื่อ เปลี่ยนเป็นหน้ากากกระสอบเย็บตะเข็บ มีเขาสีม่วงดำ แถบทองและตาทอง พร้อมชุดม่วงเข้ม ลอยข้างตัว หมุนตามทิศผู้เล่น และก้มเงยหัวตามการมองในช่วง -30 ถึง 30 องศา หุ่นเดิมที่ยังอยู่จะปรับรูปลักษณ์เมื่ออัปเดตตามผู้ใช้ครั้งถัดไป

รุ่นนี้เพิ่มข้อมูลภาพโดเมนแบบใหม่ ต้องอัปเดตเป็น 0.5.4-domain-debug ทั้ง Client และ Server ทุกคน รุ่นเก่าเก็บไว้ในโฟลเดอร์ release ตามเดิม คำสั่ง Debug และ HUD ยังใช้ได้ทั้งหมด

## แก้ทิศหน้ากากและตรวจดีบัฟ — 0.5.4

แก้การหมุนโมเดลส่วน head จาก 180 เป็น 0 องศา เพื่อแก้หน้ากากหันกลับด้าน โดยคงการหมุนตามผู้เล่นไว้ ยังต้องตรวจการสวมจริงในเกม

เพิ่ม /thida debug status <ชื่อผู้เล่นเป้าหมาย> ให้แสดงเวลาที่เหลือของดาเมจลดลง ตีช้า เลือดไหล รับดาเมจแรงขึ้น ตาบอด และค่า Attack speed ปัจจุบัน สถานะเลือดไหล/ตีช้า/รับดาเมจแรงขึ้นเป็นค่าภายใน ไม่ได้มีไอคอน Potion ของตัวเอง

กฎเดิม: ผู้เล่นที่เชื่อมนรตราต้องเป็นผู้โจมตี และทั้งผู้โจมตีกับเหยื่อต้องอยู่ในโดเมน หุ่นอื่นต้องไม่ถูกล็อกจากกาฝากหรือพันธะ จึงส่งครบสามชุด (ดาเมจลดลง+ตีช้า / เลือดไหล+ตาบอด / รับดาเมจแรงขึ้น) ธิดาตีเองให้ดาเมจลดลง+ตาบอด ระบบนี้ปัจจุบันรองรับเป้าหมายผู้เล่น ยังไม่รองรับมอนสเตอร์ จึงไม่ได้เปลี่ยนกฎการโจมตีระหว่างตรวจรายงานนี้
