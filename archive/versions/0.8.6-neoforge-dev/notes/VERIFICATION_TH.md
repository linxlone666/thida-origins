# ผลตรวจ 0.8.6 — สัดส่วนฟอนต์และชื่อกาฝาก

- Itim provider size ยังเป็น 11 เท่ารุ่น 0.8.5 ไม่แก้ HUD scale ที่บันทึกในโปรไฟล์จริง แต่ฟอนต์ต่างตระกูลมีความกว้างต่างกัน: ข้อความทดสอบเดียวกันใน log เดิม ThaiFontFix=57 และ Itim=71 หน่วย GUI (ไม่ใช่การเทียบความสูงหรือ HUD scale)
- ขยายการจองช่อง HP ตามเลขที่กว้างที่สุดจาก 0–9 และจำนวนหลักของ Max HP พร้อมป้องกันการตัดค่าด้วย ellipsis หากพื้นที่ไม่พอจะ fit เฉพาะข้อความนั้นให้แสดงครบ
- client วัด `100 / 100` ได้ 47 หน่วย มีช่องจอง 52 หน่วย และผ่าน assertions สำหรับ Max HP 100, 999, 1000, 9999, 1000000 กับ HP หลายค่า
- ภาพ `screenshots/after-single.png` แสดง `100 / 100` ในการ์ดความกว้างขั้นต่ำ ภาพ `after-many.png` แสดง `100 / 100`, `16 / 20` และ HP หลายหลักครบ
- ชื่อ `item.thida.parasite_doll` ทั้งสอง locale และใน JAR เป็น “ตุ๊กตากาฝาก” ตัดเฉพาะคำต่อท้ายชื่อ ไม่แก้ผลแบ่งปันความเสียหาย
- build และ unit tests 37 รายการผ่าน รวม assertion ชื่อไอเทมใหม่
- ตรวจภาพ client เมื่อไม่มีแพ็กเสริมผ่าน และเมื่อเปิด ThaiFontFix-1.0.8 หลังแก้ fallback ผ่าน 2 รอบเริ่มเกมใหม่ รวม GUI Scale 2/3, HUD scale 60/100/140%, การลากและเปิด editor ใหม่
- ระหว่างตรวจ ThaiFontFix รอบแรกพบ native FreeType crash จึงเปลี่ยน fallback จาก `minecraft:default` เป็น `minecraft:include/unifont` เพื่อไม่อ้าง TTF default ของแพ็กข้าม font sets; primary Itim size 11 เดิม รอบหลังแก้ไม่เกิดซ้ำทั้งสองครั้ง
- ตรวจโปรไฟล์ DRC แบบอ่านอย่างเดียว พบ Thida 0.8.5, GUI Scale 3 และเปิด ThaiFontFix ไม่ได้ติดตั้ง JAR หรือแก้ options ของโปรไฟล์จริง
- ยังไม่ได้ทดสอบ DRC ทั้งแพ็กพร้อมม็อดทุกตัวหรือเล่นหลายเครื่อง และไม่ได้รัน GameTests ฝั่งเซิร์ฟเวอร์ซ้ำในรอบแก้ UI นี้

ไฟล์ JAR และ source ZIP อยู่ข้างเอกสารนี้ ใช้ JAR 0.8.6 แทนรุ่นเดิม โดยไม่เก็บ JAR Thida สองรุ่นไว้พร้อมกัน อ่านรายละเอียดไฟล์ที่เปลี่ยนและวิธีคำนวณได้ใน `FONT_HP_0_8_6_TH.md`
