# คู่มือ Passive นรตราและนิลกาล — Thida Origins

เอกสารภาษาไทยแยกสำหรับ Passive 1 และ Passive 2 อ้างอิงโค้ดในซอร์สโปรเจกต์ `thida` ณ วันที่ 16 ตุลาคม 2569 รวมวิธีใช้สำหรับผู้เล่นและจุดเชื่อมต่อสำหรับผู้พัฒนาต่อ

## สถานะเวอร์ชัน

ซอร์สและการตรวจสอบปัจจุบันใช้ Minecraft 1.20.1, Forge 47.4.0 และ Java 17 เป้าหมายในอนาคตคือ Minecraft 1.21.1 NeoForge ซึ่งยังไม่ได้ย้ายในงานนี้ ใช้ไอคอน โมเดล และรูปไอเทมเดิม ระบบเอฟเฟกต์เพิ่มเติมมีเพียงจุดเชื่อมต่อ ยังไม่มี dependency หรือไฟล์เอฟเฟกต์ AAA Particles

เอกสารนี้ระบุกฎของ Passive ทั้งสอง สกิลอื่นและ ULT ต้องใช้ข้อกำหนดของตนเอง โดย ULT ยังไม่ตัดสินใจ

## การรับและใช้ไอเทม

| Passive | ชื่อภาษาไทยของไอเทม | ชื่อภาษาอังกฤษของไอเทม |
| --- | --- | --- |
| นรตรา / Narotra | ตุ๊กตานรตรา | Narotra Doll |
| นิลกาล / Nilakan | ตุ๊กตานิลกาล | Nilakan Doll |

ผู้ใช้ต้องเลือก Origin ธิดา ระบบตรวจผ่านสิทธิ์ Origin เดิมของม็อด ไอเทมได้รับอัตโนมัติเมื่อระบบแจกชุด Passive ครั้งแรก คราฟต์ด้วยสูตรเดิมได้ หรือรับผ่าน `/thida kit` ซึ่งตรวจ Origin ก่อนแจก

ต้องถือหุ่นเพื่อเริ่มเชื่อม หลังเชื่อมสามารถเก็บหุ่นไว้ในช่องเก็บของของผู้เล่นได้ เมื่อต้องการยกเลิก ให้ถือหุ่น เปิดเมนูหุ่นฟางด้วยปุ่มที่ตั้งไว้ใน Controls (ค่าเริ่มต้น R) แล้วกด 1 หรือเลือกปุ่มยกเลิกสายสัมพันธ์

## Passive 1 — นรตรา / Narotra

### การเชื่อมเป้าหมาย

ถือหุ่นนรตราในมือหลักหรือมือรอง แล้วจ้องผู้เล่นเป้าหมายโดยตรงต่อเนื่อง 10 วินาที หรือ 200 ticks เป้าหมายต้องอยู่ห่างไม่เกิน 15 บล็อก มองเห็นได้โดยตรง และไม่มีสิ่งกีดขวาง เป้าหมายไม่จำเป็นต้องมองกลับ

หากหันหลุด เป้าหมายออกระยะ ถูกบัง หรือเปลี่ยนหุ่นที่ถือระหว่างเชื่อม ความคืบหน้าจะถูกล้าง เมื่อเข้าเงื่อนไขอีกครั้งต้องเริ่มนับใหม่ หุ่นที่เชื่อมแล้วเปลี่ยนเป้าหมายไม่ได้จนกว่าจะยกเลิกสายสัมพันธ์เดิม

### การฟื้นมานา

เมื่อเชื่อมสำเร็จ ธิดาและเป้าหมายได้รับมานา 5% ของ Max Mana ของผู้รับแต่ละคนทันที จากนั้นฟื้นซ้ำทุก 20 วินาทีขณะสายสัมพันธ์ทำงาน

สูตรคือ `มานาที่ฟื้น = Max Mana ของผู้รับ × 0.05` เช่น Max Mana 250 ฟื้นครั้งละ 12.5 มานา และจำกัดมานาหลังฟื้นไม่ให้เกิน Max Mana อัตราการฟื้นมีตัวจับเวลาร่วมต่อผู้เล่น การมีหลายสายสัมพันธ์จึงไม่เพิ่มจำนวนครั้งที่ผู้เล่นได้รับมานาในช่วง 20 วินาทีเดียวกัน

การฟื้นมานาใช้แอตทริบิวต์ `irons_spellbooks:max_mana` และข้อมูลมานาของ Iron’s Spells ’n Spellbooks หากไม่มีม็อดหรือ API ที่ใช้ได้ ส่วนฟื้นมานาจะไม่ทำงาน แต่การเชื่อมและการล้างดีบัฟยังทำงานได้

### การล้างดีบัฟ

ล้างให้ธิดาผู้ใช้เท่านั้น รอบแรกพร้อมล้างทันทีหลังเชื่อม แต่ถ้ายังไม่มีดีบัฟจะรอ เมื่อมีดีบัฟจึงล้างและเริ่มคูลดาวน์ 20 นาที หลังครบกำหนด ถ้ามีดีบัฟจะล้างทันที หากยังไม่มีจะรอจนมีแล้วล้าง ทำซ้ำขณะสายสัมพันธ์ทำงาน

## Passive 2 — นิลกาล / Nilakan

### การเชื่อมเป้าหมาย

ถือหุ่นนิลกาลในมือหลักหรือมือรอง แล้วโจมตีผู้เล่นเป้าหมาย ระยะที่เซิร์ฟเวอร์ยอมรับไม่เกิน 10 บล็อก ไม่ตรวจเส้นสายตา ใช้เหตุการณ์พยายามโจมตีโดยตรง จึงเชื่อมได้แม้การโจมตีไม่สร้างดาเมจ เช่น เป้าหมายใช้โล่หรือมีสถานะอมตะ

ระยะ 10 บล็อกเป็นขีดจำกัดการตรวจของ Passive โค้ดนี้ไม่ได้เพิ่มระยะโจมตีพื้นฐานของ Minecraft ผู้เล่นยังต้องสามารถส่งการโจมตีเป้าหมายผ่านระบบโจมตีของเกมหรือระบบระยะโจมตีที่ใช้อยู่ได้

หุ่นที่เชื่อมแล้วเปลี่ยนเป้าหมายไม่ได้จนกว่าจะยกเลิกสายสัมพันธ์เดิม การโจมตีซ้ำไม่เพิ่มโบนัส

### โบนัสขณะสายสัมพันธ์ทำงาน

ธิดาผู้ใช้ได้รับความเร็วเคลื่อนที่ +5% และดาเมจประชิด +5% ผ่านตัวปรับแอตทริบิวต์แบบ `MULTIPLY_TOTAL` โดยมี UUID คงที่ต่อโบนัส จึงไม่เพิ่มตัวปรับซ้ำจากนิลกาล โบนัสจากแหล่งอื่นยังทำงานร่วมกันตามกฎแอตทริบิวต์ของ Minecraft

### การล้างดีบัฟ

ล้างให้ธิดาผู้ใช้เท่านั้น รอบแรกพร้อมล้างเมื่อธิดามีดีบัฟ หลังล้างเริ่มคูลดาวน์ 10 นาที เมื่อครบกำหนดแล้ว ถ้ายังไม่มีดีบัฟจะรอจนมีจึงล้างและเริ่มรอบใหม่

## กฎร่วมและการบันทึกสถานะ

| เหตุการณ์ | พฤติกรรม |
| --- | --- |
| เปลี่ยนมือหรือเก็บหุ่นในช่องเก็บของ | คงสายสัมพันธ์และผล หากยังมีหุ่นชิ้นที่เชื่อมอยู่กับตัว |
| โยนหุ่นที่เชื่อมออกจากตัว | ยกเลิกสายสัมพันธ์ของหุ่นนั้นทันที พร้อมข้อความแจ้ง |
| เป้าหมายออฟไลน์ ตาย หรือเป็นผู้ชม | คงสายสัมพันธ์ แต่พักผล |
| ผู้ใช้และเป้าหมายอยู่คนละมิติ | คงสายสัมพันธ์ แต่พักผล |
| ระยะห่างเกิน 200 บล็อก | คงสายสัมพันธ์ แต่พักผล |
| เป้าหมายกลับมาอยู่ในเงื่อนไขที่ใช้ได้ | กลับมาทำงานตามข้อมูลและตัวจับเวลาที่บันทึกไว้ |
| ผู้ใช้ธิดาออกเกม | คงสายสัมพันธ์และตัวจับเวลา กู้คืนเมื่อกลับเข้าเกม |
| ผู้ใช้ตาย | คัดลอกข้อมูล Passive ไปยังผู้เล่นหลังเกิดใหม่ ผลต้องมีหุ่นชิ้นเดิมอยู่ในช่องเก็บของจึงทำงาน |
| ผู้ใช้เสีย Origin ธิดา | ลบสายสัมพันธ์และถอดโบนัส Passive |
| หุ่นชิ้นที่เชื่อมไม่อยู่ในช่องเก็บของ แต่ไม่ใช่เหตุการณ์โยน | ผลพักไว้ สายสัมพันธ์ยังถูกเก็บ |

เซิร์ฟเวอร์เก็บ UUID เป้าหมาย UUID ประจำหุ่น สถานะพัก/ทำงาน และเวลาพร้อมของแต่ละผลในข้อมูลผู้เล่น ตัวจับเวลาใช้ ticks ของโลก Overworld: 20 ticks เท่ากับหนึ่งวินาทีตามความเร็วเกมปกติ เวลาที่เซิร์ฟเวอร์ปิดไม่ถูกนับเป็น ticks

ระหว่างพักจะไม่ฟื้นมานา ไม่ล้างดีบัฟ และถอดโบนัสนิลกาลออก กำหนดเวลาที่บันทึกไว้ยังคงเดิม หากครบกำหนดระหว่างพัก ผลที่พร้อมจะทำงานเมื่อสายสัมพันธ์กลับมาใช้ได้ตามเงื่อนไขของผลนั้น

การล้างดีบัฟใช้ระบบเดิมของม็อด: ลบสถานะ Minecraft ประเภท `HARMFUL` ลบเลือดไหล การลดความเร็วโจมตี ความอ่อนแอ และความเปราะบางที่ม็อดนี้เก็บไว้ พร้อมดับไฟ สถานะพิเศษของม็อดอื่นที่ไม่ได้จัดเป็น `HARMFUL` และไม่ได้ใช้ข้อมูลเหล่านี้ต้องเพิ่ม integration แยก

ปัจจุบันข้อมูลผู้ใช้เก็บสายสัมพันธ์นรตราหนึ่งรายการและนิลกาลหนึ่งรายการ พร้อม UUID หุ่นที่เกี่ยวข้อง จึงยังไม่รองรับการผูกหุ่นชนิดเดียวกันหลายชิ้นของผู้ใช้คนเดียวกับหลายเป้าหมายพร้อมกัน

## จุดเชื่อมต่อเอฟเฟกต์สำหรับผู้พัฒนา

กฎเกมอยู่ใน `src/main/java/dev/thida/ThidaPassives.java` และส่งเหตุการณ์ผ่าน `ThidaPassiveEffects` บนเซิร์ฟเวอร์ จากนั้น `ThidaNetwork.PassiveEffectEvent` ส่งให้ผู้ใช้และเป้าหมายที่เกี่ยวข้อง ฝั่ง client รับผ่าน `ThidaClientEffects` และเรียก `ThidaPassiveEffectAdapter` ค่าเริ่มต้นเป็น adapter ที่ไม่ทำอะไร ระบบ Passive จึงทำงานได้เมื่อไม่มีไฟล์เอฟเฟกต์

### ชื่อเหตุการณ์

| ชื่อ | ความหมาย |
| --- | --- |
| `NAROTRA_ATTEMPT_STARTED` | เริ่มนับการจ้องนรตรา |
| `NAROTRA_LINKED` | นรตราเชื่อมสำเร็จ |
| `NAROTRA_LINK_FAILED` | การพยายามเชื่อมนรตราถูกยกเลิกหรือไม่สำเร็จ |
| `NAROTRA_MANA_RESTORED` | ฟื้นมานาจากนรตรา |
| `NAROTRA_DEBUFF_CLEANSED` | นรตราล้างดีบัฟธิดา |
| `NILAKAN_ATTEMPT_STARTED` | เริ่มพยายามเชื่อมนิลกาล |
| `NILAKAN_LINKED` | นิลกาลเชื่อมสำเร็จ |
| `NILAKAN_LINK_FAILED` | เชื่อมนิลกาลไม่สำเร็จ |
| `NILAKAN_DEBUFF_CLEANSED` | นิลกาลล้างดีบัฟธิดา |
| `LINK_CANCELLED` | การพยายามเชื่อมถูกยกเลิก ส่งร่วมกับเหตุการณ์ล้มเหลวเฉพาะชนิด |
| `LINK_PAUSED` | สายสัมพันธ์พักผลชั่วคราว |
| `LINK_RESUMED` | สายสัมพันธ์กลับมาทำงาน |
| `LINK_ENDED` | สายสัมพันธ์สิ้นสุด |

หากผูกเอฟเฟกต์กับทั้งเหตุการณ์ล้มเหลวเฉพาะชนิดและ `LINK_CANCELLED` ต้องป้องกันการแสดงเอฟเฟกต์ซ้ำ

### ข้อมูลในเหตุการณ์

| ฟิลด์ NBT | ความหมาย |
| --- | --- |
| `event` | ชื่อเหตุการณ์ |
| `passive` | `NAROTRA` หรือ `NILAKAN` |
| `owner` | UUID ผู้ใช้ธิดา |
| `target` | UUID เป้าหมาย หากทราบ |
| `dimension` | รหัสมิติของตำแหน่งเหตุการณ์ |
| `x`, `y`, `z` | จุดยึดเอฟเฟกต์: เหตุการณ์ฟื้นมานาใช้ตำแหน่งผู้รับมานา เหตุการณ์อื่นใช้ตำแหน่งธิดา |
| `hand` | `MAIN_HAND`, `OFF_HAND` หรือข้อความว่าง |
| `reason` | รหัสสาเหตุ หรือข้อความว่าง |

รหัสสาเหตุที่ใช้ เช่น `ITEM_SWITCHED`, `LOOK_LOST`, `OBSTRUCTED`, `OUT_OF_RANGE`, `TARGET_OFFLINE`, `TARGET_UNAVAILABLE`, `DIMENSION_CHANGED`, `OWNER_UNAVAILABLE`, `ORIGIN_REQUIRED`, `ORIGIN_LOST`, `UNLINK_BEFORE_RETARGETING`, `PLAYER_UNLINKED`, `DOLL_TOSSED` และ `DEBUG_END` ห้ามเพิ่มชื่อผู้เล่น ข้อมูลช่องเก็บของ หรือข้อมูลส่วนตัวอื่นลงใน packet เอฟเฟกต์

### การเพิ่ม AAA Particles ภายหลัง

ติดตั้ง adapter จากขั้นตอนตั้งค่าฝั่ง client ด้วย `ThidaClientEffects.installAdapter(event -> ...)` ให้ import และเรียก API ของ AAA Particles อยู่ภายใน adapter เท่านั้น เลือกเอฟเฟกต์จาก `event`, `passive` และ `reason` แสดงที่ `dimension` และ `x/y/z` หากต้องติดตามเป้าหมาย ให้ค้น entity ด้วย `target` เฉพาะเมื่อ entity นั้นอยู่ในมิติที่แสดงผล

วางทรัพยากรเอฟเฟกต์ของธิดาไว้ภายใต้ `src/main/resources/assets/thida/` โดยโฟลเดอร์ `particles/` ใช้สำหรับทรัพยากรอนุภาคที่ตรงกับรูปแบบที่เลือก ไฟล์เอฟเฟกต์และการลงทะเบียนเฉพาะ AAA Particles ต้องจัดตาม schema ของเวอร์ชันที่จะนำมาใช้ ตำแหน่งนี้เป็นแนวทางจัดทรัพยากร ยังไม่ใช่การยืนยันว่า AAA Particles โหลดไฟล์จากโฟลเดอร์ดังกล่าวโดยอัตโนมัติ

ก่อนเพิ่ม dependency ให้ตรวจเอกสารทางการเรื่องความเข้ากันได้กับ Minecraft 1.21.1 NeoForge, API ฝั่ง client และรูปแบบ resource แล้วเพิ่ม dependency การตั้งค่า resource และ adapter ตามเวอร์ชันนั้น ไม่มี signature ของ AAA Particles ที่กำหนดไว้ล่วงหน้าในโค้ดปัจจุบัน

## ผลตรวจสอบและงานที่เหลือ

การคอมไพล์ unit tests และ GameTest ผ่านบน Minecraft 1.20.1 Forge โดย GameTest ผ่านทั้งหมด 37 รายการ ครอบคลุมส่วนที่เกี่ยวข้อง เช่น การเชื่อมจากการโจมตี การจ้องและยกเลิก โบนัสนิลกาล การพัก/กลับมาทำงาน การเสีย Origin การโยนหุ่น และรอบล้างดีบัฟ ส่วน unit tests ตรวจการคำนวณ 5% Max Mana ขอบเขตระยะ และเงื่อนไขพร้อมล้างดีบัฟ

ยังต้องทดสอบกับ Iron’s Spells ’n Spellbooks ที่ติดตั้งจริงเพื่อยืนยันการอ่านและเขียนมานาตลอดเส้นทาง รวมถึงตรวจการออกเกม/กลับเข้าเกมและเกิดใหม่ด้วยผู้เล่นจริงในสภาพแวดล้อมเป้าหมาย การย้ายไป Minecraft 1.21.1 NeoForge และการเชื่อม AAA Particles ยังเป็นงานถัดไป
