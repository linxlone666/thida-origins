# การเชื่อมม็อดมานาและพลังเวทย์ส่วนตัว

งานรอบนี้ยึด text สองไฟล์ที่เจ้าของงานส่งวันที่ 18 ตุลาคม 2569 รวมคำยืนยันก่อนหน้า
การส่งม็อดส่วนตัวและสูตรจริงภายหลังเป็นงานเชื่อมระบบรอบถัดไป ไม่ต้องใช้ Iron’s Spellbooks เพื่อเปิดเกมหรือใช้สายสัมพันธ์
ไม่กำหนดสูตรมานา พลังเวทย์ เพดาน หรือค่าฮีลที่เจ้าของงานยังไม่ได้ให้

## 1. มานาสำหรับ Passive นรตรา

ติดตั้งบนเซิร์ฟเวอร์ด้วย `ThidaManaIntegration.install(Adapter)`:

```java
public interface Adapter {
    double maxMana(ServerPlayer player);
    boolean restore(ServerPlayer player, float amount, float maximum);
}
```

- `maxMana` ต้องอ่าน Max Mana ปัจจุบันของผู้รับจากม็อดส่วนตัว รวมผลค่าสถานะที่ม็อดนั้นกำหนดแล้ว
- ระบบธิดาคำนวณ 5% ให้เอง ผู้รับแต่ละคนใช้ Max Mana ของตน ไม่ใช้ Max Mana ของธิดาแทนทุกคน
- `restore` เพิ่มมานาฝั่งเซิร์ฟเวอร์และจำกัดไม่ให้เกิน `maximum` คืน true หากรองรับการดำเนินการ
- รอบ 20 วินาทีและกฎไม่เร่งอัตราจากหลายแหล่งอยู่ใน `ThidaPassives` ผู้ทำ adapter ไม่ต้องเริ่ม timer อีกชุด
- adapter ส่วนตัวมีลำดับก่อนความเข้ากันได้กับ Iron’s เสมอ ค่า Max Mana ไม่ถูกต้อง/ยังไม่พร้อมจะไม่ย้อนกลับไปเติมอีกระบบ
- หากไม่มี adapter ส่วนตัว แต่ติดตั้ง Iron’s ที่เข้ากันได้ จะใช้ adapter เดิมเป็นตัวเลือกสำรอง
- หากไม่มีทั้งสองระบบ เฉพาะการฟื้นมานาจะรอระบบมานา การเชื่อม การล้างดีบัฟ โบนัสนิลกาล และ Skill 2/3 ยังทำงาน
- `install(null)` ถอด adapter ส่วนตัว กลับไปใช้ความเข้ากันได้แบบ optional

## 2. ค่าร่ายและสเกลเวทย์ Skill 1

ใช้ `ThidaSkillIntegration.install(Adapter)` แยกจากการฟื้นมานาของ Passive
`quote(caster, doll, spell)` ต้องเป็นการอ่านค่าโดยไม่หักมานา เพราะเมนูสอบถามได้หลายครั้ง
คืน `Optional<Quote>`: percent, healHp, bleedHp, payment
หักมานาจริงเฉพาะ `Payment.consume()` เมื่อเซิร์ฟเวอร์รับคำขอร่ายที่ผ่านเงื่อนไขแล้ว คืน false หากจ่ายไม่ได้
ต้องตรวจและจ่ายในขั้นตอนเดียวบน server thread ห้ามเชื่อข้อมูลยอดมานาจาก client

เลขคาถาภายใน 0/1/2 ตรงกับคาถา 2/3/4 ในเอกสาร ชนิดหุ่นคือ `narotra_doll` และ `nilakan_doll`
ตัวตั้งต้นที่ยืนยันคือผลเปอร์เซ็นต์ 0.20 และเลือดไหล 2 HP ต่อวินาที
สูตรที่ใช้พลังเวทย์ เพดาน ค่าร่าย และฐาน/จำนวนฮีลให้เชื่อมเมื่อได้รับข้อมูลจริง
ปัจจุบันไม่มี adapter จึงปิดการร่ายพร้อมเหตุผล ไม่สมมติให้ร่ายฟรีหรือใช้สูตร Iron’s

`parasiteBreakReduction(caster, target)` รับผิดชอบสูตรลดดาเมจเป้าหมาย 10 วินาทีหลังกาฝากแตก
ยังไม่มีสูตรจึงคืน Optional.empty ไม่กำหนดเปอร์เซ็นต์แทนเจ้าของงาน
ค่าตัวอย่างใน GameTest ใช้ทดสอบเท่านั้น ไม่ลงทะเบียนใน JAR สำหรับเล่นจริง

## 3. การฮีลจากม็อดอื่นกับ Skill 3

สกิลฮีลควรเรียก `ThidaHealing.apply(caster, target, amount, Kind.SKILL)`
หรือครอบการฮีลเดิมด้วย `ThidaHealing.withSource(caster, Kind.SKILL, action)`
ใช้ NON_SKILL เฉพาะฮีลที่ไม่ใช่สกิล เช่น ยา/ธรรมชาติ ซึ่งม็อดส่งแหล่งมาอย่างถูกต้อง

- ผู้รับหทัยฮีลตัวเองด้วยสกิลถูกปฏิเสธ
- ผู้อื่นฮีล ให้ฮีลก่อนแล้วจบพันธะ
- ไม่ทราบผู้ฮีล ให้ฮีลก่อนแล้วจบตามที่เจ้าของงานยืนยัน อาจทำให้สกิลฮีลตนเองที่ไม่ระบุผู้ร่ายสำเร็จหนึ่งครั้ง
- ไม่อ้างว่าสามารถรู้ผู้ฮีลจากทุกม็อดโดยไม่มีการเชื่อมข้อมูล

## 4. เอฟเฟกต์และ HUD

ดู `SKILL_EFFECT_ADAPTER_TH.md` สำหรับ event ฝั่งเซิร์ฟเวอร์และ adapter ภาพ/เสียงฝั่ง client
รวมเริ่มพยายามเชื่อมหทัย ช่วยชีวิต เริ่มอมตะ หมดอมตะ และจบพันธะ
หมดอมตะส่งไปยังผู้รับได้แม้ธิดาออฟไลน์หรือพันธะสิ้นสุดไปแล้ว
แผงผู้รับอยู่กึ่งกลางเหนือบริเวณเลเวล/หัวใจ และลากแนวตั้งในเมนูจัดตำแหน่งเพื่อเว้นพื้นที่ Fragment ของโปรไฟล์ได้
ค่าตำแหน่งบันทึกในเครื่อง ไม่เปลี่ยนกฎเกมฝั่งเซิร์ฟเวอร์
