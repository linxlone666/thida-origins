# Thida Origins 0.8.2 — HUD ตามเนื้อหาและพื้นที่จอ

## ขอบเขต

ปรับจากซอร์ส 0.8.1 ที่ `I:\Back-ups\Work\Minecraft Origin\thida` เฉพาะการแสดงผล HUD, หน้าจัด HUD, ข้อความ และการทดสอบ ไม่แก้คลาสกติกาสกิล ดาเมจ คูลดาวน์ หรือโครงสร้างเซฟสายสัมพันธ์ ไม่มี dependency ใหม่

## วิธีลดพื้นที่

- สายสัมพันธ์: วัดชื่อและบรรทัดรายละเอียดด้วย `Minecraft.font.width` รวมพื้นที่ไอคอน หน้าสกิน ช่องว่าง และ padding ใช้แถวกว้างที่สุดร่วมกัน ขั้นต่ำ 158 และเพดาน 224 หน่วย GUI; หน้าจอแคบมีสิทธิ์ลดต่ำกว่าขั้นต่ำเพื่อไม่หลุดจอ
- แถบ HP ยาวไม่เกิน 108 หน่วย GUI เดิมยาว 147 หน่วยในกรอบ 208 หน่วย ลดความยาวภายนอกประมาณ 27%; การเปลี่ยน HP เปลี่ยนเฉพาะสัดส่วนที่เติม
- ช่องตัวเลข HP กันความกว้างตามหลักของ Max HP โดยมีขั้นต่ำ 3 หลักและเพดานการจอง 7 หลัก ไม่เปลี่ยนตาม HP ปัจจุบันทุกครั้ง ข้อมูลเต็มยังอยู่ใน snapshot; กรณียาวเกินการ์ดตัดเฉพาะภาพ
- ชื่อยาวตัดด้วย `…` ตาม font จริง ไม่เขียนทับชื่อในข้อมูล
- แผงหนึ่งแถวชื่อสั้นเริ่มได้ที่ 158 หน่วย เทียบกับความกว้างเดิม 208 หน่วย ลดประมาณ 24%; กรณีชื่อยาวอาจใช้ถึงเพดานเพื่อให้อ่านได้ ไม่บังคับให้ทุกกรณีแคบกว่าเดิม
- สถานะพักผล/ออฟไลน์ยังอ่านได้ และแสดงว่าไม่ทราบ HP ปัจจุบัน ไม่วาดหลอดเลือดจากค่าที่ cache ไว้
- แผงผู้รับ: สร้างเฉพาะกลุ่มสถานะที่มีอยู่จริง (ช่วยชีวิต, กันดีบัฟ, ความเร็ว, อมตะ) วัด label + icon + ช่องเวลาคงที่ แล้วจัดแถวใหม่ด้วย `HudPacking.flow` เพดานปกติ 248 หน่วย GUI
- หน้าจอเตี้ยใช้แถวกว้างขึ้นสำหรับหลายสถานะ แล้ว fit ทั้งชุดให้อยู่ระหว่างเป้าเล็งกับแถบ vanilla เพื่อไม่ลดขนาดตัวอักษรเกินจำเป็น ไม่ขยายกรอบเพียงเพราะชื่อผู้เล่นรายการเดียว
- HUD ผลสกิลใช้กลุ่มไอคอน + ชื่อผล/คำว่าพัก + เวลา มีความกว้างตามเนื้อหา ไม่เผื่อช่องให้สถานะที่ไม่มีแล้ว ช่องเวลากันไว้ด้วยความกว้าง `888:88` จึงไม่สั่นทุกวินาที
- พันธะสิ้นสุดจะไม่มีป้ายช่วยชีวิต เหลือเฉพาะบัฟที่ยังมีเวลา ส่วนพันธะที่ยังทำงานจะแสดงช่วยชีวิตพร้อม/ใช้แล้ว แม้ไม่มีบัฟตามเวลา

## ตำแหน่งและ editor

- ปุ่ม H และการเปลี่ยนปุ่มใน Controls คงเดิม
- `ThidaHudLayout` ใช้ขนาด GUI หลังคำนวณ scale กันขอบจอ พื้นที่เป้าเล็ง และบริเวณแถบ vanilla ตรงกลางด้านล่าง
- เมื่อด้านล่างแผงสายสัมพันธ์ไม่พอ แผงผลสกิลย้ายไปช่องว่างด้านขวา พร้อม fit ตามพื้นที่ที่เหลือ ไม่ทับแผงสายสัมพันธ์
- แผงผู้รับยึดกึ่งกลางแนวนอนและขอบล่างตาม offset ของผู้เล่น ความสูงเปลี่ยนแล้วขอบล่างยังเดิม ค่า `recipientHudOffsetY` ในรุ่นนี้อ้างขอบล่างของแผง (รุ่นเดิมอ้างขอบบน) จึงอาจเห็นแผงเดิมขยับขึ้น; ปรับได้ด้วย H
- ขนาดที่ตั้งยังอยู่ในช่วง 60–140% หากพื้นที่จริงไม่พอจะ fit ภาพให้เล็กลง และ editor แจ้งเปอร์เซ็นต์ที่แสดงจริงด้วยคำว่า “พอดีจอ” ไม่เปลี่ยนค่าที่ผู้เล่นตั้งไว้
- ภาพ กรอบเลือก พื้นที่รับเมาส์ และการจำกัดขอบจอใช้ geometry เดียวกัน กลุ่มผลสกิลที่แยกเป็นหลายการ์ดรับเมาส์และตีกรอบเฉพาะการ์ดจริง ไม่รับคลิกช่องว่างท้ายแถว
- ลาก ปรับขนาด คืนค่า และบันทึกยังแยกสามแผง ตัวอย่างใช้ชื่อสั้น ชื่อยาว HP หลายหลัก สถานะออฟไลน์ และหลายบัฟ เป็นข้อมูล client ชั่วคราวภายใน editor เท่านั้น
- คำสั่ง preview HUD เดิมเปิด editor แทนการนำตัวอย่างไปทับ HUD ระหว่างเล่น

## อักษรส่วนเกิน

ตรวจโค้ด HUD, badge, preview และ locale ของ 0.8.1 ไม่พบ literal เดี่ยว `ท` หรือ `จ` ที่ใช้เป็น marker ในฐานนี้ จึงไม่อ้างว่าพบต้นทางของอักษรเฉพาะตัวจากภาพที่ไม่ได้ให้มาในงานนี้

พบจุดเสี่ยงจริงใน `ThidaHud`: วาดคำว่า “รอ” ลงช่องกว้างเพียง 12 หน่วย และวาด `badge.key` ลงช่อง 8 หน่วย การตัดคำในช่องเล็กทำให้เกิดข้อความสั้นที่อ่านไม่ออก จึงเลิกวาดป้ายย่อยเหล่านี้ ใช้ชื่อผลและคำว่า “พัก” ที่วัดความกว้างครบแทน ป้ายอมตะระบุชื่อจริงด้วย ไม่แสดงเครื่องหมาย `!` แทนชื่อผล

`ThidaGui.text` ข้าม null, ข้อความว่าง และช่องที่เล็กกว่าเครื่องหมาย ellipsis แทนการวาดเศษข้อความ ไม่มีการค้นหาแล้วลบอักษรไทยทั่วโปรเจกต์ ไม่มีการเปลี่ยน font หรือ resource pack ของเกม

## ไฟล์ที่เกี่ยวข้อง

- `src/main/java/dev/thida/ThidaBondHud.java`: วัดแถวสายสัมพันธ์/กลุ่มผู้รับและวาดด้วยขนาดจริง
- `ThidaHud.java`: การจัดการ์ดผลสกิล การวัด label/เวลา และ geometry ของตัวอย่าง
- `ThidaHudLayout.java`: fit พื้นที่ GUI และหลบแถบ vanilla/เป้าเล็ง
- `HudPacking.java`: คำนวณเพดานความกว้างและจัดแถวแบบไม่พึ่ง Minecraft สำหรับ unit tests
- `ThidaHudEditor.java`: hit test ตามการ์ดจริง แสดงเปอร์เซ็นต์ fit และเก็บ anchor ขอบล่างของแผงผู้รับ
- `ThidaGui.java`: ป้องกันข้อความว่าง/ช่องแคบเกินอ่าน
- `assets/thida/lang/th_th.json`, `en_us.json`: ป้ายไทยตรงกันทั้งสอง locale
- `src/test/java/dev/thida/HudPackingTest.java`: 4 unit tests สำหรับ geometry
- `src/gametest/java/dev/thida/HudPreviewSmoke.java`: ชุดทดสอบภาพใน client จริง เปิดเฉพาะ dev run `runHudPreview` ไม่บรรจุใน JAR
- `gradle.properties`: รุ่น 0.8.2; `tools/Package-Handoff.ps1`: รวมคู่มือนี้ในซอร์สส่งมอบ

## การทดสอบภาพซ้ำ

ใช้โลกทิ้งได้ชื่อ `hud-preview` ใน `run-neoforge-hud-preview/saves` แล้วรัน `runHudPreview -PwithoutIron=true` ด้วย Java 21 ตัวอย่าง HUD ฉีดเฉพาะ snapshot ฝั่ง client ไม่สร้างสายสัมพันธ์ ไม่ร่ายสกิล และไม่ส่งคำขอไปเซิร์ฟเวอร์ การตั้งโหมด survival เปลี่ยนเฉพาะโลกทดสอบที่คัดลอกมา เพื่อให้แถบหัวใจ/อาหารปรากฏในการตรวจภาพ

ภาพเก็บใน `run-neoforge-hud-preview/screenshots` ชุดทดสอบตรวจชื่อสั้น/ยาว, HP 1234/9999, หนึ่ง/หลายสายสัมพันธ์, หนึ่ง/หลายบัฟ, ผลค้างหลังพันธะจบ, ช่วยชีวิตใช้แล้วแต่ไม่มีบัฟ, GUI Scale 2/3, HUD 60/100/140%, หน้าต่าง 1280×720 และ 854×480, การลาก/ปรับขนาดแยกแผง และขอบเขตไม่ทับเป้าเล็งหรือกันเอง

ทดสอบการโหลดค่าหลังปิดเกมเต็มด้วยไฟล์คาดหวัง `hud-persistence-v2.properties` ใน run directory: รันจบหนึ่งครั้งแล้วรันใหม่ จะตรวจ config ที่โหลดตั้งแต่เริ่มและบันทึก `THIDA_HUD_RESTART_PASS` ก่อนตั้งค่าตัวอย่างใหม่ ไฟล์และโลกนี้ไม่อยู่ในชุดส่งมอบ

ผลตรวจสุดท้ายและภาพแนบอยู่ใน `HUD_VERIFICATION_TH.md` ของชุดส่งมอบ แยกภาพจำลองข้อมูลใน client ออกจากการทดสอบกติกาฝั่งเซิร์ฟเวอร์อย่างชัดเจน
